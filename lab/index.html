Things I build

I write agent skills: reusable instructions that come with their own checks. They turn my lecture notes into interactive physics visualisers, verified practice questions and study guides. Below are the skills, how they connect, and what they have built so far.

  • 4 custom skills
  • 10 interactive visualisers
  • 6 physics cores unit-tested in Node before any UI

01How the skills connect

Each skill is a written procedure that the agent follows, including the tests it must run before it is allowed to publish anything. They hand work to each other: one lecture PDF becomes a study page, and from that page I can request a visualisation or a question set.

  1. Lecture-note PDFs ↓ lecture-notes-to-doc ↓ LaTeX-style study page with in-place answers
    dispatches briefs to physics-visualiser ↓ Interactive visualiser page practice-questions ↓ Practice page with tracking
  2. Any source: syllabus, past paper, OA list ↓ practice-questions
  3. Year 1–3 notes library + Physics Skill Tree ↓ physics-module-study-guide ↓ Teaching study guide for one module
  4. Scheduled agent tasks ↓ study coach (Telegram bot) ↓ A morning plan, then it checks my replies

02The four skills

Each one fixes the order of work and the checks the agent must pass before it publishes anything. The engineering is in the checks.

physics-visualiser

One concept, one interactive page, with the physics tested first

In
A brief: the concept, the lecture’s equations and symbols, the cases it discusses, the insight to show.
Out
A page with the equations in KaTeX, a canvas, 2–4 sliders, presets for each lecture case, live readouts, “What to notice” and a collapsed “Model and assumptions”.

Why trust it: all the physics lives in a core.js with no DOM code, and it has to pass a Node test suite before any UI is built. Conservative systems use symplectic integrators (velocity Verlet or leapfrog), so energy doesn’t drift.

“A pretty animation with wrong dynamics is worse than none, because the student will trust it.”
How it checks itself
  • Uses the analytic solution whenever one exists, and simulates only what has no closed form.
  • Matches the integrator to the system: Verlet or leapfrog for Hamiltonian mechanics, RK4 for damped or driven systems, eigenstate expansion, split-step Fourier or Crank–Nicolson for time-dependent QM. Never explicit Euler for oscillatory motion.
  • The test file must print three things: drift in a conserved quantity under 1e-3 over at least 20 periods (or the right decay rate if damped), an analytic benchmark such as a period or the small-amplitude limit, and the correct qualitative behaviour for every preset.
  • A fixed physics timestep, decoupled from the frame rate; sub-stepping when the speed slider is high; boundary conditions stated on the page.
lecture-notes-to-doc

Lecture PDFs become a page that reads like the LaTeX original, and answers back

In
A lecture-notes PDF.
Out
A study page in Latin Modern, with numbered equations and the printed page numbers in the margin. Select a passage, ask a question, and the answer appears in place. On request it hands briefs to the visualiser and practice-question skills.

Why trust it: fidelity comes first. The rendered page image, not the extracted text, is the ground truth for every equation. The agent’s additions are labelled and never mixed into the lecturer’s text, and suspected errors in the notes are kept as written and flagged, not silently fixed.

How it checks itself
  • It rasterises every page with maths, figures or handwriting, because text extraction garbles subscripts, fractions and vectors.
  • A skipped algebra step gets a marked STEP note after the equation, and the lecturer’s lines are never edited.
  • Any claim the agent adds is checked numerically where possible: “If you say you checked something, you must have run the check.”
  • The page is built by a tested build kit that is restored byte for byte, matched by SHA-256, never retyped. A build that reports TeX errors isn’t published.
  • Visualisations are made only when I ask for one, each by a background agent briefed with the lecture’s own equations and notation.
practice-questions

Practice questions where every answer key is recomputed before it ships

In
Any source: lecture notes, a syllabus, a topic checklist, a past paper or an interview prep list.
Out
An interactive practice page with 20 questions by default (40% core, 40% exam-standard, 20% stretch): practice, timed, drill and review modes, hints, and spaced repetition.

Why trust it: a separate verify.py recomputes every answer independently of how it was written. It uses exact fractions, and probability answers also get a Monte Carlo run of at least 200k trials that must agree within 4 standard errors. A question that fails is fixed or dropped.

“A wrong answer key is worse than no question.”
How it checks itself
  • Each wrong multiple-choice option is a real mistake (a forgotten conditioning, a factor of 2, an off-by-one), so a wrong answer gets a diagnosis rather than just a cross.
  • Multiple-choice checks: exactly one option equals the verified answer, and no two options are numerically equal. Expressions are checked for equivalence at 20 random points.
  • Answers are accepted in any reasonable format: 3/8, 0.375, 37.5% or 3.75e-1.
  • Extra questions generated inside the page are badged “Unverified” until they have been through verify.py.
  • It never claims to reproduce a real exam’s or firm’s questions, only questions “in the style of”.
physics-module-study-guide

A study guide that teaches a whole module, prerequisites first

In
A module code or name, read from my indexed library of Year 1–3 notes.
Out
A guide that someone who missed the lectures could learn from: prerequisites from the Skill Tree, then per topic why it matters, the ideas, key derivations, a worked example and common mistakes. It ends with a key-formulae table with sources.

Why trust it: every formula in the table is checked against its source page for factors of 2 and π, signs, ħ versus h, and SI versus Gaussian units. For a whole module, a second agent that hasn’t seen the draft compares the table with the PDFs and reports mismatches.

“It is not a recap sheet.”
How it checks itself
  • Notes are looked up through a per-module index rather than by browsing, so it reads the primary notes first and secondary material only to fill gaps.
  • Equation-heavy pages are rendered as images before any formula is written down: never “rebuild an equation from memory when the notes have it”.
  • Every prerequisite named must be a real node in the Skill Tree, and every exam claim must trace back to the course’s own exam notes.
  • Background that isn’t in the notes is labelled “(not in the notes)”, and notation clashes between modules are pointed out.
