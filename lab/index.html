Things I build

Four agent skills I wrote for my physics degree, and what they produce from lecture notes: interactive visualisers, practice question sets and study guides. Each skill specifies a procedure and the tests its output must pass.

  • 4 skills

01How the skills connect

Each skill is a written procedure, including tests the output must pass before it is published. lecture-notes-to-doc converts a lecture PDF into a study page and, on request, passes briefs to physics-visualiser and practice-questions.

  1. Lecture-note PDFs ↓ lecture-notes-to-doc ↓ LaTeX-style study page, inline questions
    dispatches briefs to physics-visualiser ↓ Interactive visualiser page practice-questions ↓ Practice page with tracking
  2. Other sources: syllabus, past paper, OA list ↓ practice-questions
  3. Year 1–3 notes library + Physics Skill Tree ↓ physics-module-study-guide ↓ Study guide for one module
  4. Scheduled agent tasks ↓ study coach (Telegram bot) ↓ Morning study plan via Telegram; replies checked

02The four skills

Inputs, outputs, and the checks each skill applies before publishing.

physics-visualiser

Interactive simulation page for one physics concept

In
A brief: the concept, the lecture’s equations and symbols, the cases it discusses, the insight to show.
Out
A page with the equations in KaTeX, a canvas, 2–4 sliders, presets for each lecture case, live readouts, “What to notice” and a collapsed “Model and assumptions”.

Verification: the physics is in a separate core.js (no DOM code) that must pass a Node test suite before the UI is built. Conservative systems use symplectic integrators (velocity Verlet, leapfrog).

Details
  • Uses the analytic solution whenever one exists, and simulates only what has no closed form.
  • Matches the integrator to the system: Verlet or leapfrog for Hamiltonian mechanics, RK4 for damped or driven systems, eigenstate expansion, split-step Fourier or Crank–Nicolson for time-dependent QM. Never explicit Euler for oscillatory motion.
  • Required test output: relative drift in a conserved quantity below 1e-3 over at least 20 periods (or the expected decay rate if damped), an analytic benchmark such as a period or small-amplitude limit, and the expected behaviour for every preset.
  • A fixed physics timestep, decoupled from the frame rate; sub-stepping when the speed slider is high; boundary conditions stated on the page.
lecture-notes-to-doc

Lecture-notes PDF to a LaTeX-style web page

In
A lecture-notes PDF.
Out
A study page in Latin Modern with numbered equations and the printed page numbers in the margin. Any passage can be selected and queried inline. On request it passes briefs to the visualiser and practice-question skills.

Verification: equations are transcribed from rendered page images, not extracted text. Additions are labelled and kept separate from the lecturer’s text; suspected errors in the notes are flagged rather than corrected.

Details
  • Pages with maths, figures or handwriting are rasterised and read as images, since text extraction garbles subscripts, fractions and vectors.
  • Skipped algebra steps get a marked STEP note after the equation; the lecturer’s lines are not edited.
  • Claims added by the agent are checked numerically where possible.
  • Pages are built with a tested build kit restored byte for byte (SHA-256 matched). Builds with TeX errors are not published.
  • Visualisations are built only on request, by a background agent given the lecture’s equations and notation.
practice-questions

Practice question sets with independently verified answers

In
Any source: lecture notes, a syllabus, a topic checklist, a past paper or an interview prep list.
Out
An interactive page, 20 questions by default (40% core, 40% exam-standard, 20% stretch), with practice, timed, drill and review modes, hints and spaced repetition.

Verification: verify.py recomputes every answer independently, with exact fractions; probability answers also need a Monte Carlo check (≥ 200k trials, agreement within 4 standard errors). Failing questions are fixed or dropped.

Details
  • Each wrong multiple-choice option corresponds to a specific mistake (missed conditioning, a factor of 2, an off-by-one), which is shown when it is chosen.
  • Multiple-choice checks: exactly one option equals the verified answer, and no two options are numerically equal. Expressions are checked for equivalence at 20 random points.
  • Answers are accepted in any reasonable format: 3/8, 0.375, 37.5% or 3.75e-1.
  • Extra questions generated inside the page are badged “Unverified” until they have been through verify.py.
  • Questions are original; none are presented as a real exam’s or firm’s questions.
physics-module-study-guide

Study guide for one module, built from the course notes

In
A module code or name, read from my indexed library of Year 1–3 notes.
Out
A guide ordered by prerequisites (from the Skill Tree). Per topic: motivation, explanation, key derivations, a worked example and common mistakes. Ends with a key-formulae table with sources.

Verification: each formula in the table is checked against its source page (factors of 2 and π, signs, ħ vs h, SI vs Gaussian units). For a whole module, a second agent that has not seen the draft compares the table with the PDFs.

Details
  • Sources are chosen from a per-module index: primary notes first, secondary material only to fill gaps.
  • Equation-heavy pages are read as images before any formula is written down.
  • Every prerequisite named must be a real node in the Skill Tree, and every exam claim must trace back to the course’s own exam notes.
  • Material not in the notes is labelled “(not in the notes)”; notation clashes between modules are noted.
